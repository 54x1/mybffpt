## SOC 2 Type 2 findings (operating effectiveness)

Type 2 requires controls to have *run* over an observation window with retained evidence.
Current honest state: **the window has not started.** Gaps:

- **T2-1 (High):** No release tag or GitHub Release → no change-management baseline;
  direct pushes to `dev` bypass the PR control (M1/M2 above are prerequisites).
- **T2-2 (Medium):** CI evidence exists only while workflows pass. The unit suite is
  red at audit date (4 failures in `pdfStatement.test.ts`) — if CI was green, local and
  CI diverge; either way, capture the CI run logs for the window and keep `verify` green.
- **T2-3 (Medium):** Vulnerability-management evidence: weekly `security-schedule.yml`
  runs audit/SBOM, but the SBOM artifact in repo predates today's lockfile change;
  regenerate (`npm run sbom`) and let the weekly job accumulate dated artifacts.
- **T2-4 (Medium):** No monitoring/recovery test on record (A1.3) — perform the first
  redeploy-from-tag test once M5 exists, and log it in `EVIDENCE_GUIDE.md`.
- **T2-5 (Low):** Recurring PII dumps (AG-1) show the disposal control depends on manual
  habit; consider making the pdfdiag harness write to a temp dir outside the repo.

**Recommended Type 2 plan:** close M1–M6 → tag `v1.x` → run ≥ 8–12 weeks with weekly
security jobs, PR-only changes, signed commits, and archived CI/SBOM/audit artifacts →
then engage an assessor. Evidence retention per `EVIDENCE_GUIDE.md`.
