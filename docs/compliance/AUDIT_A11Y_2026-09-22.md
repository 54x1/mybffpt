## Findings fixed during this audit

| Ref | Severity | Finding | Fix |
|---|---|---|---|
| A11Y-A | Critical (axe `aria-valid-attr-value`) | While the onboarding tour overlay is open, **no** tab panel is mounted — every header tab's `aria-controls="panel-*"` dangles; axe flags the active tab as critical. Reproduced deterministically via "Get Started Now". | `AppHeader` gains a `tourOpen` prop (wired from `showTour` in `App.vue`); `aria-controls` is omitted while the overlay replaces all panels. |
| A11Y-B | Serious (axe `label`) | The Share Codes result modal's readonly code `<input>` (`ShareCodeModal.vue`) had no accessible name — visible label was a sibling `<span>` with no `for`. | Added `aria-label="Share code"` to the input. |
| A11Y-C | Moderate (WCAG 4.1.2 / dialog semantics) | The two Add-form dialogs (`managerRef` "Manage Categories/Tags", `renameConfirmRef` "Update References?") lacked `aria-modal`, `aria-labelledby`, and focus-return — the only dialogs in the app missed by the earlier `useDialogA11y` pass. | Added ids to both `<h3>` headings, `aria-modal="true"` + `aria-labelledby` on both `<dialog>`s, and routed their opens through `useDialogA11y().openDialog()`. |
| A11Y-D | Moderate (WCAG 2.1.1) | BulkEditModal's tag-removal control is a `<span role="button" tabindex="0">` with Enter but **no Space** activation — keyboard users pressing Space got nothing. | Added `@keydown.space.stop.prevent="unpickAddTag(tag)"`. |
| A11Y-E | Moderate (WCAG 2.4.3 / 4.1.2) | The onboarding overlay (`OnboardingHero.vue`) is a custom fixed-position `role="dialog" aria-modal="true"` — **not** a native `<dialog>` — and never moved focus into itself on open. Its inner `tabindex="-1"` div was dead markup; SR/keyboard users stayed behind the overlay, and Tab could reach content underneath (no native trap). | Moved `tabindex="-1"` to the dialog section itself and focus it in `onMounted`. Escape-to-skip already existed. Full native-`<dialog>` conversion remains a candidate follow-up (see Open items). |

## Findings documented, not fixed (design-decision or rewrite-sized)

| Ref | Severity | Finding | Rationale for deferral |
|---|---|---|---|
| A11Y-F | Moderate | `role="radio"` buttons in AdvancedSettingsModal's Filter-Logic radiogroup have no roving tabindex / arrow-key navigation (APG radio-group pattern). Tab reaches each radio individually — usable, but non-standard for SR users expecting arrows. | Correct implementation needs focus-state tracking per group; small rewrite with regression risk on a modal that is otherwise axe-clean. Documented in ACCESSIBILITY.md. |
| A11Y-G | Moderate | AppHeader date-format/theme `role="listbox"` buttons and TransactionsSection `details.dropdown` `role="menu"`/`menuitem` items lack arrow-key navigation (APG listbox/menu patterns). Native `<summary>` gives Enter/Space open + Escape close, so all functions remain keyboard-reachable. | Same as F: APG-conformant composite widgets are a component rewrite; current state is functional-but-unpolished rather than blocking. |
| A11Y-H | Low (hygiene) | `TagPickerModal.vue` is unreachable dead code — nothing in `src/` ever sets `tagPicker.open = true`; only `closeTagPicker()` writes the flag. Its a11y wiring (useDialogA11y, watcher re-open) is complete but never exercised. | Deletion touches ~8 App.vue call sites + props surface; flagged for removal in a cleanup pass rather than mixed into an accessibility fix set. |
| A11Y-I | Known (carried) | Theme contrast: cupcake `primary` #65c3c8 = 1.93:1; chart white-on-`warning` badges 1.66:1. Excluded from the automated gate, documented since the first a11y pass. | Design decision across 28 DaisyUI themes; needs per-theme contrast audit + luminance-based badge text color. Unchanged. |
| A11Y-J | Low (carried) | Two ~200ms D3 hover transitions in `ChartsSection.vue` not gated by `prefers-reduced-motion`. | Cosmetic micro-feedback; listed for completeness. |

## Regression coverage added

- **`tests/e2e/a11y-deep.spec.ts`** — 10 tests that seed the exact precondition for each
  previously-unscanned modal/view and run a full axe analysis. Notable flow facts encoded:
  loading demo data auto-switches to the Chart tab (must click back); row-selection
  checkboxes exist in mobile + desktop copies (`:visible` selector); the "Manage
  categories" button lives inside the closed category `details.dropdown`; the manager
  dialog's own accessible name collides with its trigger under `getByLabel` (scope to
  `getByRole('button', …)`).
- **`tests/e2e/node-shims.d.ts`** — ambient module shims so e2e specs can use four Node
  built-ins without adding `@types/node` to the browser-only tsconfig (precedent:
  `pdfdiag.test.ts`).

## Open items (accessibility)
